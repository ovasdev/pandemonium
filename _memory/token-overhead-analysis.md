# Анализ перерасхода токенов в Pandemonium Bot

**Дата:** 2026-04-06  
**Автор:** Bot Administrator  
**Статус:** Исследование завершено

---

## Контекст

Эмпирическое наблюдение: токены через pandemonium-bot расходуются заметно быстрее, чем при работе напрямую через Claude Code CLI. Проведено исследование кодовой базы бота для выявления источников overhead.

---

## Выявленные источники перерасхода

### 1. Инъекция персоны + души через `--append-system-prompt`

**Файл:** `src/pandemonium/tgbot/session/manager.py` (метод `_build_persona_prompt`)

Каждый запрос к Claude Code через бот добавляет содержимое PERSONA.md + SOUL.md через флаг `--append-system-prompt`. Это **дополнительный системный промпт**, которого нет при обычной работе с CLI.

| Персона | Размер PERSONA.md | Размер SOUL.md | Итого |
|---------|-------------------|----------------|-------|
| bot-administrator | ~14 KB | — | ~2,000 токенов |
| Типичная персона | 3-7 KB | 3-9 KB | 900-2,200 токенов |

**Overhead: 500-2,200 токенов на каждый запрос.**

При обычной работе в CLI персоны не инжектируются — пользователь сам управляет системным промптом.

### 2. Массивная директория `.agent/` индексируется Claude Code

**Размер `.agent/` pandemonium-bot:** ~1.4 MB  
(46 скилов, 10+ персон, 15+ душ, workflows, rules)

Claude Code при запуске индексирует содержимое рабочей директории, включая `.agent/`. В обычном проекте без `.agent/` этого overhead нет.

**Overhead: 500-5,000 токенов** (зависит от того, сколько Claude Code решит загрузить в контекст).

### 3. Накопление контекста в сессии без компрессии

**Файл:** `src/pandemonium/tgbot/session/manager.py` (строки 51-53, 325, 351)

Бот использует `--resume` для продолжения сессий. При этом:
- Каждое новое сообщение добавляет к контексту все предыдущие
- Нет автоматической компрессии или очистки старого контекста
- Пользователь должен вручную вызвать `/clear`

В CLI Claude Code тоже накапливает контекст, но CLI имеет встроенную компрессию, которая может работать иначе при subprocess-режиме.

**Overhead: экспоненциальный рост.** 5 запросов подряд = ~25,000+ входных токенов только от контекста.

### 4. Флаг `--verbose`

**Файл:** `src/pandemonium/tgbot/claude/process.py` (строки 59-65)

```python
cmd = [
    "claude",
    "--print",
    "--output-format", "stream-json",
    "--verbose",          # <-- лишние токены
    "--max-turns", "50",
    "--permission-mode", "bypassPermissions",
]
```

Флаг `--verbose` включает расширенный вывод, что может увеличивать объём reasoning-токенов.

**Overhead: 100-500 токенов на запрос.**

### 5. `--max-turns 50` разрешает длинные цепочки

В CLI по умолчанию используется меньшее число turns. Бот разрешает до 50 agentic turns, что позволяет Claude тратить больше токенов на сложные задачи без явного контроля пользователя.

### 6. Permission round-trips

**Файл:** `src/pandemonium/tgbot/session/manager.py` (строки 433-476)

Хотя бот работает в `bypassPermissions`, при необходимости подтверждения создаётся цикл:
1. Claude запрашивает разрешение
2. Бот отправляет кнопки в Telegram
3. Пользователь нажимает Allow/Deny
4. Бот передаёт ответ в stdin Claude

Каждый такой round-trip поддерживает процесс в памяти, и контекст продолжает накапливаться.

## Сводная таблица overhead

| Источник | На запрос | За 10 запросов | Управляем? |
|----------|-----------|----------------|------------|
| Персона + душа | 500-2,200 | 5,000-22,000 | Да |
| `.agent/` индексация | 500-5,000 | 5,000-50,000 | Частично |
| Накопление контекста | 2,500+ (растёт) | 50,000+ | Да |
| `--verbose` | 100-500 | 1,000-5,000 | Да |
| `--max-turns 50` | 0-10,000 | 0-100,000 | Да |
| Permission round-trips | 100-300 | 1,000-3,000 | Частично |
| **Итого (оценка)** | **4,000-18,000** | **62,000-230,000** | — |

**Сравнение:** при прямом использовании CLI без `.agent/`, без персон, с ручной очисткой контекста — overhead на эти же 10 запросов составляет ~0 токенов сверх полезной нагрузки.

## Рекомендации

### Быстрые (low-effort)

1. **Убрать `--verbose`** — экономия 100-500 токенов на запрос
2. **Автоочистка сессий** — после N запросов или M токенов автоматически сбрасывать сессию
3. **Уменьшить `--max-turns`** — поставить 10-20 вместо 50

### Средние (medium-effort)

4. **Сделать инъекцию персоны опциональной** — добавить флаг в конфиг
5. **Создать `.claudeignore`** — исключить неиспользуемые скилы/персоны из индексации
6. **Оптимизировать PERSONA.md** — сократить bot-administrator с 14 KB до 3-4 KB

### Архитектурные (high-effort)

7. **Lazy-loading скилов** — загружать только скилы, релевантные текущей персоне
8. **Контекстная компрессия** — реализовать суммаризацию старых сообщений при приближении к лимиту
9. **Токен-бюджет на персону** — раздельный учёт overhead и полезных токенов

---

## Заключение

Основные причины перерасхода — **накопление контекста без компрессии** (главный фактор), **инъекция персон/душ** и **индексация массивной `.agent/`**. Суммарный overhead может составлять **60-230K токенов** на 10 последовательных запросов в одной сессии, что полностью объясняет наблюдаемый перерасход относительно прямого использования CLI.
