# Pandemonium Tagging System

Система маркировки документов, дополняющих Agent Skills. Обеспечивает навигацию, фильтрацию и семантическую связь между скилами и их расширениями.

---

## Проблема

Скил — это `SKILL.md` + опциональные `references/`, `scripts/`, `assets/`. Но вокруг скила накапливаются документы, которые не являются его частью, а **развивают** его: воркфлоу, примеры, шпаргалки, теоретические статьи, методологические заметки. Без единой системы маркировки эти документы теряют связь с контекстом — непонятно, к какому скилу они относятся, что они из себя представляют, и в каком дискурсе существуют.

---

## Три оси тегирования

Каждый документ, дополняющий скил, маркируется тегами по трём ортогональным осям:

### 1. Skill Tag — привязка к скилу

Уникальный тег, идентифицирующий скил, который документ дополняет. Формат: `#skill/<skill-name>`.

```
#skill/analytical-psychology
#skill/pandemonium-dev
#skill/aiogram-patterns
#skill/existential-psychotherapy
```

Правила:
- Один документ — один skill tag (документ дополняет ровно один скил)
- `<skill-name>` совпадает с именем директории скила в `.agent/skills/`
- Если документ релевантен нескольким скилам — он дополняет тот, к которому относится **основная** тема; остальные указываются через `related:` в метаданных

### 2. Document Type Tag — тип документа

Определяет, **что** представляет собой документ. Фиксированная таксономия:

| Тег | Назначение | Пример |
|-----|-----------|--------|
| `#type/workflow` | Пошаговый процесс, сценарий работы | Воркфлоу терапевтической сессии |
| `#type/reference` | Справочный материал, таблицы, API | Таблица когнитивных искажений |
| `#type/example` | Конкретный пример применения скила | Разбор кейса ABC-анализа |
| `#type/theory` | Теоретическая база, концепции | Теория архетипов Юнга |
| `#type/cheatsheet` | Краткая шпаргалка, быстрый доступ | Шпаргалка по aiogram middleware |
| `#type/template` | Шаблон для генерации артефактов | Шаблон SKILL.md |
| `#type/glossary` | Определения терминов | Глоссарий экзистенциальной терапии |
| `#type/methodology` | Описание метода, подхода, фреймворка | Методология РЭПТ |
| `#type/case-study` | Подробный разбор случая | Случай групповой динамики |
| `#type/exercise` | Практическое задание, упражнение | Упражнение на диспутирование |

Правила:
- Один документ — один type tag (выбирать доминирующий тип)
- Таксономия расширяется только через обновление этого документа

### 3. Domain Tag — направление дискурса

Определяет, **в каком смысловом поле** существует документ. Открытая таксономия — новые теги добавляются по мере появления новых доменов.

**Текущие домены:**

| Тег | Область |
|-----|---------|
| `#domain/психология` | Психология, психотерапия, когнитивистика |
| `#domain/философия` | Философия, эпистемология, этика |
| `#domain/математика` | Математика, логика, статистика |
| `#domain/физика` | Физика, механика, оптика, квантовая теория |
| `#domain/химия` | Химия, радиохимия |
| `#domain/программирование` | Разработка, архитектура ПО, DevOps |
| `#domain/музыка` | Музыка, вокал, композиция, саунд-дизайн |
| `#domain/информатика` | CS: алгоритмы, структуры данных, ИИ |
| `#domain/медицина` | Радиология, медицинская физика |
| `#domain/мифология` | Мифология, символизм, культурология |
| `#domain/gamedev` | Игровой дизайн, нарратив, механики |
| `#domain/администрирование` | Управление ботом, конфигурация, персоны |

Правила:
- Один документ может иметь **несколько** domain tags (междисциплинарность)
- Новые домены добавляются свободно, но перед добавлением — проверить, не покрывает ли существующий домен нужную область

## Формат метаданных документа

Каждый дополняющий документ содержит YAML-frontmatter:

```yaml
---
title: "Название документа"
skill: analytical-psychology          # skill tag (без префикса #skill/)
type: workflow                        # document type (без префикса #type/)
domains:                              # domain tags (без префикса #domain/)
  - психология
  - мифология
related:                              # опционально: связанные скилы
  - existential-psychotherapy
  - group-psychotherapy
created: 2026-04-03
---
```

**Полная тег-строка** (для поиска, индексации, отображения):

```
#skill/analytical-psychology #type/workflow #domain/психология #domain/мифология
```

## Размещение документов

Документы, дополняющие скил, размещаются внутри директории скила:

```
.agent/skills/analytical-psychology/
├── SKILL.md                          # основной скил
├── references/                       # справочные материалы (часть скила)
│   └── archetypes-table.md
├── extensions/                       # дополняющие документы (расширения)
│   ├── workflow-therapy-session.md   # #type/workflow
│   ├── example-shadow-integration.md # #type/example
│   └── theory-collective-unconscious.md # #type/theory
└── scripts/
```

Конвенция именования файлов в `extensions/`: `<type>-<краткое-описание>.md`

```
workflow-abc-analysis.md
reference-cognitive-distortions.md
example-disputation-case.md
theory-four-ultimates.md
cheatsheet-aiogram-filters.md
```

## Поиск и фильтрация

Теги обеспечивают три вектора поиска:

**По скилу** — все документы, дополняющие конкретный скил:
```
grep -r "skill: analytical-psychology" .agent/skills/
```

**По типу** — все воркфлоу во всех скилах:
```
grep -r "type: workflow" .agent/skills/
```

**По домену** — все документы в области психологии:
```
grep -r "психология" .agent/skills/*/extensions/
```

**Комбинированный** — все примеры в домене программирования:
```
grep -rl "type: example" .agent/skills/ | xargs grep -l "программирование"
```

## Принципы расширения

1. **Один skill tag** — документ принадлежит одному скилу. Если он равно полезен двум — это сигнал разбить его на два документа или вынести общую часть в отдельный скил.

2. **Один type tag** — не существует «воркфлоу-примера». Есть воркфлоу, содержащий примеры, или пример, описывающий воркфлоу. Выбирать доминирующий формат.

3. **Множественные domain tags** — междисциплинарность поощряется. Документ по когнитивным искажениям в контексте этики: `#domain/психология #domain/философия`.

4. **Теги — не папки** — теги обеспечивают мягкую классификацию поверх жёсткой файловой структуры. Файл физически живёт в `extensions/` своего скила, а теги позволяют находить его по любой из трёх осей.

5. **Документ без тегов не существует** — каждый файл в `extensions/` обязан иметь frontmatter с `skill`, `type` и хотя бы одним `domain`.

## Пример полного документа

```markdown
---
title: "ABC-анализ: пошаговый воркфлоу"
skill: rational-emotive-therapy
type: workflow
domains:
  - психология
related:
  - cognitive-distortions-ethics
created: 2026-04-03
---

# ABC-анализ: пошаговый воркфлоу

## 1. Выявить активирующее событие (A)
...

## 2. Определить иррациональные убеждения (B)
...

## 3. Зафиксировать последствия (C)
...

## 4. Диспутирование (D)
...

## 5. Новый эффект (E)
...
```

Тег-строка: `#skill/rational-emotive-therapy #type/workflow #domain/психология`
