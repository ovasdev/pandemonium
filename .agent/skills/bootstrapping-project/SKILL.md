# Bootstrapping Project

Скил для создания агентной инфраструктуры в проекте — структуры `.agent/` и файла `CLAUDE.md`.

## Когда активировать

- "Подключи новый проект"
- "Создай структуру агентов в проекте X"
- "Инициализируй .agent/"
- "Bootstrap project"
- "Подготовь проект для работы с персонами"

## Структура `.agent/`

Создай следующее дерево каталогов в корне проекта:

```
.agent/
├── persona-registry.yaml    # Реестр персон проекта
├── personas/                # Персоны (роли агента)
│   └── {name}/
│       ├── PERSONA.md       # Определение персоны
│       └── memory/          # Память персоны (опционально)
├── skills/                  # Скилы (компетенции)
│   └── {name}/
│       ├── SKILL.md         # Определение скила
│       └── references/      # Справочные материалы (опционально)
├── souls/                   # Души (стиль мышления/общения)
│   └── {name}/
│       └── SOUL.md
├── rules/                   # Конвенции проекта
└── workflows/               # Стандартные процедуры
```

Создавай только те подкаталоги, для которых есть содержимое. Пустые `souls/`, `rules/`, `workflows/` создавать не обязательно — достаточно `personas/` и `skills/`.

## Конвенции именования

- Папки и имена сущностей: **kebab-case** (`product-owner`, `storage-app-knowledge`)
- Главные файлы: строго `PERSONA.md`, `SKILL.md`, `SOUL.md` (регистр важен)
- Имя папки скила **совпадает** с полем `name` в frontmatter

## Формат persona-registry.yaml

```yaml
# {Project Name} — Реестр персон

persona-name:
  project: project-id
  path: /absolute/path/to/project
  soul: soul-name | null
  triggers:
    - триггерная фраза 1
    - триггерная фраза 2
```

## Формат PERSONA.md

```markdown
---
name: persona-name
soul: soul-name | null
triggers:
  - триггер 1
  - триггер 2
---

# Display Name

Краткое описание роли.

## Компетенции
- Что персона знает и умеет

## Принципы
1. Ключевые правила поведения

## Скилы
| Скил | Описание |
|------|----------|
| `skill-name` | Что делает скил |

## Антипаттерны
- Чего персона НЕ должна делать
```

## Формат SKILL.md

```markdown
---
name: skill-name
description: "До 1024 символов. Что делает + когда активировать."
metadata:
  author: имя
  version: "1.0.0"
---

# Skill Name

## Когда активировать
- Список триггерных ситуаций

## Ключевые знания
Основной контент скила.

## Порядок работы
Пошаговая инструкция.
```

Описание (`description`) должно содержать **что** скил делает и **когда** его активировать. Без XML-символов (`<`, `>`). Overflow-контент → `references/`.

## CLAUDE.md

**Критически важно**: если в проекте уже существует `CLAUDE.md` — **не перезаписывай его**. Вместо этого:
1. Прочитай существующий `CLAUDE.md`
2. Добавь секцию про систему персон и структуру `.agent/` в конец файла
3. Не дублируй информацию, которая уже есть

Если `CLAUDE.md` отсутствует — создай новый со следующей структурой:

```markdown
# {Project Name} — Инструкции для агента

## Система персон

Если установлена `PANDEMONIUM_ACTIVE_PERSONA` — прочитай
`.agent/personas/$PANDEMONIUM_ACTIVE_PERSONA/PERSONA.md`.
Иначе — персона по умолчанию: **{Default Persona}**
(`.agent/personas/{default-persona}/PERSONA.md`).

Реестр всех персон: `.agent/persona-registry.yaml`.

## Проект

{Краткое описание проекта — 1-2 предложения.}

## Структура `.agent/`

{Дерево каталогов с пояснениями.}

## Правила разработки

{Tech stack, конвенции, тесты — специфично для проекта.}
```

## Common-скилы

При bootstrap **всегда копируй** в новый проект следующие скилы из pandemonium-bot:

| Скил-источник | Путь в pandemonium-bot | Что копировать |
|---------------|----------------------|----------------|
| `skill-creator` | `.agent/skills/skill-creator/` | Всю папку целиком (SKILL.md, references/, scripts/, evals/) |
| `brainstorming` | `.agent/skills/brainstorming/` | Всю папку целиком (SKILL.md, references/, evals/) |
| `managing-personas` | `.agent/skills/managing-personas/` | Всю папку целиком (SKILL.md, evals/) |

Команда копирования:
```bash
cp -r /mnt/b/projects/pandemonium-bot/.agent/skills/{skill-creator,brainstorming,managing-personas} \
  $TARGET_PROJECT/.agent/skills/
```

Эти скилы — универсальные, не привязаны к конкретному проекту. Они дают новому проекту базовые возможности: создавать скилы, проводить брейнштормы, управлять персонами.

## Персона по умолчанию: Product Owner

При bootstrap **всегда создавай** персону `product-owner` — она становится персоной по умолчанию для нового проекта.

Product Owner:
- Знает продукт на основе документации проекта (если есть `docs/`, `README.md` и т.д.)
- Формулирует требования, приоритеты, acceptance criteria
- Принимает решения о scope фич

Персоне назначаются common-скилы + скил знания проекта (если создаётся):

```markdown
## Скилы

| Скил | Описание |
|------|----------|
| `skill-creator` | Создание и улучшение скилов по спецификации Anthropic |
| `brainstorming` | Структурированные дизайн-сессии перед реализацией |
| `managing-personas` | CRUD персон в `.agent/personas/` |
| `{project}-knowledge` | Знание продукта на основе документации (создай, если есть docs/) |
```

Если в проекте есть документация (`docs/`, `README.md`, etc.) — создай скил `{project-id}-knowledge`, который ссылается на эти документы и содержит ключевые факты о продукте. Назначь его product-owner.

## Порядок работы

1. Определи корень целевого проекта (из `$PANDEMONIUM_ACTIVE_PROJECT_PATH` или явного пути)
2. Проверь, существует ли `.agent/` — если да, не пересоздавай, а дополняй
3. Проверь, существует ли `CLAUDE.md` — если да, **дополни**, не перезаписывай
4. Создай структуру каталогов
5. Скопируй common-скилы из pandemonium-bot
6. Создай персону `product-owner` с назначенными скилами
7. Если есть документация — создай скил `{project-id}-knowledge`
8. Создай `persona-registry.yaml`
9. Создай или дополни `CLAUDE.md` (персона по умолчанию — product-owner)
10. Зарегистрируй проект в pandemonium-bot (скил `managing-projects`), если ещё не зарегистрирован

## После bootstrap

Не забудь:
- Зарегистрировать новые персоны в `persona-registry.yaml` pandemonium-bot, если проект подключается к боту
- Проверить, что `CLAUDE.md` проекта не конфликтует с `CLAUDE.md` pandemonium-bot
