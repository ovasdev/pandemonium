# Creating Polylogue

Сборка и ведение многоголосых сессий, в которых одновременно участвуют несколько персон активного проекта. Полилог — не просто групповой чат: это структурированный формат с правилами вторжения, адресации, молчания и документирования.

---

## Когда применять

- Пользователь перечисляет нескольких персон и просит ответить всех или часть.
- Пользователь задаёт вопрос, требующий нескольких оптик (психолог + философ + врач; инженер + дизайнер; экзистенциалист + стоик).
- Пользователь произносит слово «полилог» или явно просит собрать группу.
- В уже идущей сессии пользователь адресует реплику конкретным участникам.

Когда **не** применять: обычный запрос одной персоне, смена персоны (`switching-personas`), административная задача (`managing-personas`).

---

## Этап 1. Сборка состава

1. Определить, кого включать:
   - Если пользователь перечислил персон — взять их.
   - Если пользователь назвал категорию («все психологи», «философы», «медики») — найти по триггерам/компетенциям в `.agent/personas/*/PERSONA.md` активного проекта и в реестре `.agent/persona-registry.yaml`.
   - Если состав неочевиден — уточнить у пользователя, а не додумывать.

2. Для каждой персоны прочитать её `PERSONA.md` полностью — принципы, компетенции, антипаттерны. Без этого голос персоны не будет различим.

3. Проверить: у каждой персоны должна быть папка `notes/` в её директории. Если нет — создать (`mkdir -p .agent/personas/<name>/notes`).

---

## Этап 2. Фиксация правил полилога

Сохранить правила в память агента как `project`-мемори (скил `remembering`), чтобы они пережили сессию:

```markdown
---
name: Polylogue participants and rules
description: Ongoing polylogue format with N personas — <list> — and rules of engagement
type: project
---

**Участники**: persona-1, persona-2, ...

**Правила**:
1. Вторжение с markdown-обоснованием — разрешено любому участнику.
2. Заметки — в `.agent/personas/<name>/notes/`.
3. Файлы в filestorage2 — с тегом персоны и в её коллекцию.
4. Адресация перед репликой — опционально; без неё отвечают те, кому есть что сказать.
5. Если нечего сказать — буквальной формулой «мне нечего сказать».

**Why:** <причина, по которой пользователь собрал именно этот состав>
**How to apply:** <как это должно влиять на поведение в сессиях>
```

Добавить ссылку в `MEMORY.md`.

---

## Этап 3. Правила ведения полилога

### Адресация

Перед каждой репликой пользователь может указать, от кого он хочет услышать ответ:
- «Ответь <персона1>, <персона2>» — отвечают только указанные.
- «Ответят психологи, остальные — если есть что сказать» — указанные отвечают обязательно, остальные — по желанию.
- Без адресации — отвечают все, кому есть что сказать по теме.

### Молчание

Если у участника **действительно** нет содержательного ответа, он говорит **буквально**: «мне нечего сказать». Не придумывает ответ ради формальности — молчание честнее пустого слова.

Критерий «есть что сказать»: тема пересекается с компетенциями персоны (скилы, принципы, триггеры в `PERSONA.md`) и персона может внести **новое** в сравнении с уже сказанным другими.

### Вторжение

Любой участник может вмешаться в разговор, если:
- Его компетенция критически релевантна пропущенной грани вопроса.
- Он видит ошибку или пропуск, которые никто другой не исправит.
- Вопрос отходит в его область.

Вторжение оформляется отдельным markdown-документом (статьёй в `notes/` или в filestorage), где в начале указано: кто вторгся, почему сейчас, что именно вносится.

### Ответ по голосам

Каждая персона отвечает **в своём голосе**: лексика, ритм, принципы, антипаттерны из её `PERSONA.md`. Не смешивать голоса, не нейтрализовать различия. Различие — ценность полилога.

## Этап 4. Форматы ответа

### Формат A: статья + краткое изложение

Пользователь просит «хотя бы одну статью на filestorage, а тут изложите кратко».

Схема:
1. Каждая отвечающая персона пишет **полноценную статью** в `.agent/personas/<name>/notes/YYYY-MM-DD-<topic>.md` с фронтматтером:
   ```yaml
   ---
   title: "..."
   author: <persona-name>
   date: YYYY-MM-DD
   tags: [polylogue, <другие теги>]
   addressee: user
   ---
   ```
2. Статьи сохраняются по правилу `Dual save` (см. `pandemonium-filestorage`): локально + filestorage2 с тегом персоны и её коллекцией.
3. В Telegram отправляется каждый файл через `$PANDEMONIUM_SEND_FILE` с caption.
4. В чате — краткие реплики (3–8 предложений на персону) в голосе каждой.

### Формат B: только реплики

Пользователь задал обычный вопрос без просьбы сохранять. Каждая отвечающая персона — реплика в своём голосе, 3–10 предложений.

### Формат C: избранные участники

Пользователь адресовал реплику части группы. Отвечают только они; остальные — только если у них есть критическая вставка, иначе молчат (даже без формулировки «мне нечего сказать» — они просто не появляются).

## Этап 5. Заметки и filestorage

### Заметки персоны

Каждый участник может писать заметки в свою папку `.agent/personas/<name>/notes/`:
- Личные наблюдения за ходом разговора.
- Гипотезы, которые ещё не готовы озвучить.
- Материалы для следующих сессий.

Формат: markdown с фронтматтером (title, author, date, tags).

### Сохранение в filestorage2

Когда персона хочет сохранить файл (статью, справку, материалы), применяется `Dual save` из скила `pandemonium-filestorage`:

1. **Локально** — через `pandemonium.filestorage.FileStorage` или прямую запись в папку `notes/`.
2. **Удалённо** (filestorage2 на малинке):
   - Обязательная коллекция: `pandemonium` (id: 2).
   - Обязательный тег: `pandemonium` (id: 10).
   - **Тег персоны**: имя персоны (например, `jung`, `ellis`, `yalom`). Если тега нет — создать, цвет `#8b5cf6`.
   - **Коллекция персоны**: отдельная коллекция на имя персоны (например, `jung`, `ellis`). Если нет — создать.
   - Дополнительно — `skill/*`, `type/*`, `domain/*` по системе тегирования.
3. **В Telegram** — отправить файл через `$PANDEMONIUM_SEND_FILE` с caption.

Если filestorage2 недоступен — сохранить локально, сообщить пользователю.

---

## Этап 6. Закрытие сессии

Явного закрытия полилог не требует — правила в памяти переживают сессию. Но если пользователь явно говорит «заверши полилог» или «разберём полилог»:

1. Убрать/пометить мемори полилога как архивное (не удалять — это история).
2. Сообщить пользователю о закрытии.
3. Если персоны создали новые заметки — оставить их как архив сессии.

---

## Типичные ошибки

| Ошибка | Как избежать |
|--------|--------------|
| Голоса персон сливаются в один нейтральный тон | Читать `PERSONA.md` каждой персоны перед ответом; использовать её лексику, принципы, запреты |
| Персона отвечает ради формальности, хотя сказать нечего | Буквально проверять: есть ли у неё уникальный вклад? Если нет — «мне нечего сказать» |
| Игнорируется адресация пользователя | Перед ответом перечитать последнюю реплику пользователя на предмет адресации |
| Файлы не попадают в filestorage с тегом персоны | Dual save с тегом и коллекцией персоны — часть протокола, а не опция |
| Полилог создаётся без фиксации правил в памяти | Формат переживает сессию только через мемори; без неё — забудется через компакцию |
| Статьи в filestorage без caption | Caption — часть контракта: title, тема, ключевая мысль |

## Пример полного цикла

**Пользователь**: «Собери всех психологов, Амосова и Сократа. Ответьте на моё самоописание статьёй на filestorage, а в чате — кратко. Ответят психологи, остальные — если есть что сказать.»

1. **Сборка**: carl-jung, albert-ellis, irvin-yalom (психологи обязательно), nikolai-amosov, socrates (по желанию). Проверить `.agent/personas/*/PERSONA.md`. Создать `notes/` где нужно.
2. **Фиксация в памяти**: `project_polylogue.md` + запись в `MEMORY.md`.
3. **Написание статей**: каждый активно отвечающий пишет статью в своей `notes/` по формату A.
4. **Dual save**: статьи → локально + filestorage2 (тег + коллекция персоны + `pandemonium`).
5. **Telegram**: каждая статья отправлена через `$PANDEMONIUM_SEND_FILE`.
6. **Чат**: краткие реплики — от психологов обязательно, от остальных — если «есть что сказать» (иначе «мне нечего сказать» или просто не появляются).
7. **Медицинское автосохранение**: если в сообщении есть соматика — обновить `medical_*` мемори (скил `medical-record`).
