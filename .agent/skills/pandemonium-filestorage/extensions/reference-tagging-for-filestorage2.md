# Тегирование файлов перед сохранением в filestorage2

Справочник по выбору тегов и коллекций при загрузке файлов на Raspberry Pi filestorage2. Основан на Pandemonium Tagging System (три оси тегирования).

## Обязательные теги и коллекции

Каждый файл, сохраняемый в filestorage2, получает:

| Что | Значение | ID |
|-----|----------|----|
| Коллекция | `pandemonium` | 2 |
| Тег | `pandemonium` | 10 |

## Три оси → теги filestorage2

Система тегирования оперирует тремя осями. Каждая ось маппится в тег filestorage2:

### 1. Skill — к какому скилу относится файл

Формат тега: `skill/<skill-name>`

Один файл → один skill tag. Имя совпадает с директорией в `.agent/skills/`.

**Дерево решений:**

```
Файл — документация/код бота?
  → skill/pandemonium-dev

Файл — персона, душа, скил (административный артефакт)?
  → skill/managing-personas | skill/managing-souls | skill/skill-creator

Файл — психологическая тема?
  ├── Аналитическая психология, архетипы, Юнг → skill/analytical-psychology
  ├── РЭПТ, ABC-модель, Эллис → skill/rational-emotive-therapy
  ├── Когнитивные искажения, логические ошибки → skill/cognitive-distortions-ethics
  ├── Экзистенциальная терапия, Ялом → skill/existential-psychotherapy
  └── Групповая терапия → skill/group-psychotherapy

Файл — точные науки?
  ├── Физика, математика, Ньютон → skill/classical-physics-mathematics
  ├── Ядерная физика, химия, радиология → skill/physics-chemistry-radiology
  └── CS, алгоритмы, ИИ → skill/computer-science

Файл — музыка, перформанс?
  → skill/music-performance

Файл — паттерны aiogram?
  → skill/aiogram-patterns

Файл — интеграция с Claude CLI?
  → skill/claude-cli-integration

Файл — Android-разработка?
  → skill/android-jetpack-compose

Файл — NestJS?
  → skill/nestjs-expert

Файл — PostgreSQL?
  → skill/postgresql

Не подходит ни один скил?
  → Не присваивать skill tag. Только pandemonium + type + domain.
```

### 2. Type — что представляет собой файл

Формат тега: `type/<type-name>`

Один файл → один type tag. Фиксированная таксономия:

| Тег | Когда использовать |
|-----|--------------------|
| `type/workflow` | Пошаговый процесс, сценарий, инструкция |
| `type/reference` | Справочник, таблица, API-документация |
| `type/example` | Конкретный пример, демонстрация |
| `type/theory` | Теория, концепция, научная статья |
| `type/cheatsheet` | Шпаргалка, краткая выжимка |
| `type/template` | Шаблон для генерации |
| `type/glossary` | Словарь терминов |
| `type/methodology` | Описание метода, фреймворка |
| `type/case-study` | Разбор конкретного случая |
| `type/exercise` | Практическое задание |
| `type/artifact` | Готовый артефакт (персона, душа, скил, конфиг) |
| `type/note` | Заметка, мысль, черновик |
| `type/media` | Изображение, аудио, видео |

**Дерево решений:**

```
Файл описывает как делать что-то шаг за шагом?
  → type/workflow

Файл — справочная таблица, список API, каталог?
  → type/reference

Файл показывает конкретный пример использования?
  → type/example

Файл — теоретическое описание, статья, концепция?
  → type/theory

Файл — краткая выжимка на одну страницу?
  → type/cheatsheet

Файл — PERSONA.md, SOUL.md, SKILL.md или подобный артефакт?
  → type/artifact

Файл — изображение, аудио, видео?
  → type/media

Файл — свободная заметка, мысль, черновик?
  → type/note
```

### 3. Domain — смысловая область

Формат тега: `domain/<domain-name>`

Один файл → один или несколько domain tags. Открытая таксономия.

| Тег | Триггеры |
|-----|----------|
| `domain/психология` | Психотерапия, когнитивистика, эмоции, поведение |
| `domain/философия` | Эпистемология, этика, онтология, экзистенциализм |
| `domain/математика` | Алгебра, анализ, геометрия, логика, статистика |
| `domain/физика` | Механика, оптика, электродинамика, квантовая теория |
| `domain/химия` | Элементы, реакции, радиохимия |
| `domain/программирование` | Код, архитектура, DevOps, базы данных |
| `domain/музыка` | Вокал, композиция, продакшн, теория музыки |
| `domain/информатика` | Алгоритмы, структуры данных, ИИ, криптография |
| `domain/медицина` | Радиология, медицинская физика, диагностика |
| `domain/мифология` | Мифы, символы, культурология, религиоведение |
| `domain/gamedev` | Игровой дизайн, нарратив, механики, D&D |
| `domain/администрирование` | Бот, конфигурация, персоны, деплой |

Если определён skill tag — домены часто следуют автоматически:

| Скил | Домены по умолчанию |
|------|---------------------|
| analytical-psychology | психология, мифология, философия |
| rational-emotive-therapy | психология, философия |

| physics-chemistry-radiology | физика, химия, медицина |
| computer-science | информатика, программирование, математика |

## Дополнительные теги (не из осей)

Помимо трёх осей, файлу можно присвоить контекстные теги:

- **Персона**: `persona`, имя персоны (`bot-administrator`, `carl-jung`, ...)
- **Душа**: `soul`, имя души (`jung`, `ellis`, ...)
- **Проект**: `pandemonium` (обязателен), имя другого проекта если релевантно

## Алгоритм тегирования

```
1. pandemonium (тег) — ВСЕГДА
2. pandemonium (коллекция) — ВСЕГДА
3. Определить skill tag по содержимому файла (дерево решений выше)
4. Определить type tag по формату файла (дерево решений выше)
5. Определить domain tags (1+) по теме
6. Добавить контекстные теги если применимо (persona, soul, ...)
7. Проверить: существуют ли теги в filestorage2?
   — Да → использовать существующий ID
   — Нет → создать через POST /api/tags
8. Присвоить все теги файлу через POST /api/files/{id}/tags
9. Добавить в коллекцию pandemonium + дополнительные коллекции
```

## Пример: сохранение воркфлоу терапевтической сессии

Файл: `workflow-therapy-session.md` — пошаговый процесс терапевтической сессии по Юнгу.

```
Теги:
  - pandemonium          (обязательный, id: 10)
  - skill/analytical-psychology  (→ создать если нет)
  - type/workflow                (→ создать если нет)
  - domain/психология            (→ создать если нет)
  - domain/мифология             (→ создать если нет)

Коллекции:
  - pandemonium          (обязательная, id: 2)
```

## Пример: сохранение персоны

Файл: `PERSONA.md` персоны carl-jung.

```
Теги:
  - pandemonium          (id: 10)
  - persona              (id: 9)
  - carl-jung            (→ создать)
  - skill/managing-personas      (→ создать если нет)
  - type/artifact                (→ создать если нет)
  - domain/администрирование     (→ создать если нет)
  - domain/психология            (→ создать если нет)

Коллекции:
  - pandemonium          (id: 2)
```
