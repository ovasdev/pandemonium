# Pandemonium Telegram bot — Требования

## 1. Общее описание

Pandemonium bot — Telegram-бот, выступающий мостом между Claude Code и пользователем, не имеющим физического доступа к своему компьютеру. Пользователь отправляет текстовые запросы через Telegram, Бот запускает Claude Code в контексте выбранного проекта, транслирует промежуточные сообщения и возвращает результат.

## 2. Роли и доступ

- Доступ к боту имеют только пользователи, указанные в конфигурационном файле (whitelist по Telegram user ID).
- Неавторизованные пользователи получают сообщение об отказе в доступе.

## 3. Конфигурация

### 3.1 Файл конфигурации

Формат: YAML. Расположение: задаётся при запуске (по умолчанию `~/.pandemonium/config.yaml`).

Содержимое:

```yaml
telegram:
  bot_token: "BOT_TOKEN"

allowed_users:
  - telegram_id: 123456789
    name: "Alice"

projects:
  - id: "my-app"
    name: "My Application"
    path: "/home/user/projects/my-app"

storage:
  base_path: "~/.pandemonium/sessions"  # корневая папка для протоколов

token_budget:
  per_request_limit: 100000     # максимум токенов на один запрос (0 = без лимита)
```

### 3.2 Проекты

- На первом этапе — один проект (один пользователь).
- Архитектура должна поддерживать несколько проектов и пользователей без переписывания ядра (см. `future.md`).

## 4. Жизненный цикл запроса

### 4.1 Отправка запроса

1. Пользователь пишет боту текстовое сообщение с запросом.
2. Бот немедленно отвечает reply-сообщением со статусом и inline-кнопкой **Cancel**.
3. Бот сохраняет запрос в файловую систему (см. п. 6 — Протоколирование).
4. Бот запускает Claude Code в контексте папки проекта, передавая запрос.
5. Во время работы Claude Code бот показывает статус "typing" (chat action).

### 4.2 Промежуточные сообщения (стриминг)

- Текстовый вывод Claude Code транслируется пользователю чанками.
- Каждый чанк отправляется отдельным сообщением (reply на исходный запрос пользователя).
- Чанки отправляются по мере накопления, с разумной задержкой (debounce ~2-3 секунды), чтобы не флудить и не упираться в rate limits Telegram.
- Все промежуточные сообщения протоколируются (см. п. 6).

### 4.3 Вопросы от Claude Code

Claude Code может задавать вопросы двух типов:

**a) Запросы разрешений (permissions)**
- Пересылаются пользователю с кнопками **Allow** / **Deny**.
- Ответ пользователя передаётся обратно в Claude Code.

**b) Уточняющие вопросы**
- Пересылаются пользователю как обычное сообщение.
- Бот ожидает текстовый ответ пользователя.
- Ответ передаётся обратно в Claude Code.
- Вопросы и ответы протоколируются с суб-номерами (N.1, N.2, ...).

### 4.4 Завершение

1. Claude Code завершает работу и формирует отчёт (markdown).
2. Бот сохраняет отчёт в файловую систему.
3. Бот отправляет отчёт пользователю как прикреплённый `.md` файл (reply на исходный запрос).
4. Статусное сообщение обновляется: **Done** (кнопка Cancel убирается).
5. Фиксируется количество использованных токенов (см. п. 7).

### 4.5 Отмена

- Пользователь нажимает кнопку **Cancel** в статусном сообщении.
- Бот завершает процесс Claude Code (SIGTERM → SIGKILL по таймауту).
- Статусное сообщение обновляется: **Cancelled**.
- Частичный результат (если есть) сохраняется в протокол.

### 4.6 Ошибки

- Если Claude Code завершился с ошибкой — пользователь получает сообщение с описанием ошибки.
- Если процесс завис (таймаут, настраиваемый в конфиге) — принудительное завершение + уведомление пользователю.
- Если бот не может запустить Claude Code (не найден, нет прав) — сообщение об ошибке.
- Все ошибки логируются в файловую систему.

## 5. Сессии

- Каждый запрос создаёт отдельную сессию Claude Code.
- Если в рамках запроса возникают вопросы/ответы — они обрабатываются в той же сессии.
- В будущем: возможность хранить сессию на уровне проекта и продолжать диалог через `--resume` (см. `future.md`).

## 6. Протоколирование (файловая система)

### 6.1 Структура папок

```
{storage.base_path}/
└── {project_id}/
    └── {request_N}/
        ├── request.md          # исходный запрос пользователя (номер N)
        ├── N.1.md              # промежуточное сообщение / вопрос от Claude
        ├── N.1.response.md     # ответ пользователя на вопрос N.1
        ├── N.2.md              # следующее промежуточное сообщение
        ├── N.2.response.md     # ответ пользователя
        ├── stream_log.md       # полный лог стриминга (все чанки)
        ├── report.md           # финальный отчёт
        ├── error.md            # описание ошибки (если была)
        └── meta.json           # метаданные: timestamps, статус, токены
```

### 6.2 meta.json

```json
{
  "request_number": 1,
  "status": "completed",
  "created_at": "2026-03-10T12:00:00Z",
  "completed_at": "2026-03-10T12:05:30Z",
  "tokens_used": {
    "input": 15000,
    "output": 3200,
    "total": 18200
  },
  "cancelled": false,
  "error": null
}
```

### 6.3 Нумерация

- Номера запросов — последовательный инкремент (1, 2, 3, ...) в рамках проекта.
- Промежуточные вопросы/ответы — суб-нумерация: N.1, N.2, N.3, ...
- Номер определяется по наличию существующих папок (max + 1).

## 7. Учёт токенов

- Для каждого запроса фиксируется количество потреблённых токенов (input + output).
- Данные берутся из вывода Claude Code (он сообщает usage в конце работы).
- Если настроен `per_request_limit` — при превышении лимита процесс прерывается, пользователь получает уведомление.
- Данные о токенах записываются в `meta.json`.

## 8. Интерфейс Telegram-бота

### 8.1 Команды

| Команда     | Описание                                      |
|-------------|-----------------------------------------------|
| `/start`    | Приветствие, проверка авторизации              |
| `/status`   | Статус текущего запроса (выполняется / свободен) |
| `/history`  | Последние N запросов с номерами и статусами    |
| `/tokens`   | Суммарный расход токенов за проект             |

### 8.2 Сообщения

- Обычное текстовое сообщение → трактуется как запрос к Claude Code.
- Reply на промежуточный вопрос → ответ передаётся в сессию Claude Code.

### 8.3 Inline-кнопки

- **Cancel** — на статусном сообщении (пока запрос выполняется).
- **Allow / Deny** — на запросах разрешений от Claude Code.

### 8.4 Chat actions

- `typing` — отображается пока Claude Code работает (обновляется каждые 5 секунд).

## 9. Технические требования

### 9.1 Запуск Claude Code

- Claude Code запускается как дочерний процесс: `claude --dangerously-skip-permissions` или через SDK, если доступен программный API.
- Рабочая директория — путь к проекту из конфига.
- Взаимодействие через stdin/stdout (JSON-stream или text, в зависимости от интерфейса Claude Code).

### 9.2 Параллельность

- На первом этапе: один запрос в один момент времени. Новый запрос при активном — ставится в ожидание или отклоняется с сообщением.
- Архитектура должна позволять переход к параллельным запросам (по одному на проект) без переписывания (см. `future.md`).

### 9.3 Стек технологий

- **Язык**: на усмотрение при реализации (рекомендация: TypeScript или Python).
- **Telegram API**: библиотека для long polling или webhooks.
- **Процессы**: управление дочерними процессами с корректным lifecycle.

### 9.4 Устойчивость

- Бот должен корректно обрабатывать перезапуск: если при старте обнаружен незавершённый запрос — пометить его как прерванный.
- Graceful shutdown: при получении SIGTERM — завершить Claude Code, уведомить пользователя.

## 10. Ограничения первой версии

- Один пользователь, один проект.
- Без параллельных запросов.
- Только текстовый ввод (без изображений и файлов).
- Без persistent-сессий между запросами.
