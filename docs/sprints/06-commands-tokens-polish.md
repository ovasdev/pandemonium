# Спринт 6 — Команды, учёт токенов, устойчивость

## Цель

Реализовать команды бота (`/status`, `/history`, `/tokens`), лимит токенов на запрос, graceful shutdown и обработку перезапуска.

## Задачи

### 6.1 Команда `/status`

- Если есть активный запрос → номер, состояние, время работы.
- Если нет → "Нет активных запросов".

```
⏳ Запрос #5 — выполняется (2 мин 30 сек)
```

### 6.2 Команда `/history`

- Последние 10 запросов из БД.
- Формат: номер, статус, дата, токены.

```
#5  ✅ completed  10.03.2026  18200 tokens
#4  ❌ error      10.03.2026  5100 tokens
#3  🚫 cancelled  09.03.2026  2300 tokens
```

### 6.3 Команда `/tokens`

- Суммарный расход по проекту из БД (input + output + total).
- Расход за текущий запрос (если есть).

```
Проект: my-app
Всего запросов: 12
Токены: 245 000 (input: 180 000, output: 65 000)
```

### 6.4 Лимит токенов на запрос

В `_run_session` (SessionManager):
- Из промежуточных `AssistantEvent.usage` суммировать текущие токены.
- Если `config.token_budget.per_request_limit > 0` и сумма превышает лимит:
  1. `claude_process.cancel()`.
  2. Статус → ERROR.
  3. Сообщение пользователю: "Превышен лимит токенов ({limit}). Запрос остановлен."
  4. Протоколирование в error.md и meta.json.

### 6.5 Graceful shutdown

Обработка сигналов SIGTERM / SIGINT:

1. Установить флаг "shutting down" — новые запросы не принимаются.
2. Для активной сессии:
   - Отправить пользователю: "Pandemonium bot перезапускается. Запрос #N прерван."
   - `claude_process.cancel()`.
   - Сохранить частичный протокол, статус → ERROR с пометкой "shutdown".
3. Закрыть соединение с БД.
4. Остановить polling бота.

### 6.6 Восстановление после перезапуска

В `main.py` при старте:
- Запросить из БД все записи со статусом `running` или `awaiting_input`.
- Обновить их статус на `error`, `error_text = "Pandemonium bot was restarted"`.
- Записать error.md и обновить meta.json для каждого.
- (Опционально) отправить пользователю уведомление, если chat_id известен.

### 6.7 Таймаут запроса

Добавить в конфиг:
```yaml
timeouts:
  request_max_seconds: 1800  # 30 минут
```

В `_run_session`: `asyncio.wait_for(process_task, timeout=config.timeouts.request_max_seconds)`.
При таймауте — `cancel()`, статус ERROR, уведомление.

### 6.8 Retry для Telegram API

В `bot/formatters.py` или отдельном utility — декоратор/wrapper:
- При `TelegramRetryAfter` — ждать указанное время.
- При `TelegramNetworkError` — retry до 3 раз с exponential backoff.
- При прочих — логировать, не ронять сессию.

## Критерий готовности

- `/status`, `/history`, `/tokens` работают корректно.
- При превышении лимита токенов — запрос останавливается с уведомлением.
- При SIGTERM — бот корректно завершается, пользователь уведомлён.
- После перезапуска — незавершённые запросы помечены как ошибки.
- Таймаут на запрос работает.
- Ошибки Telegram API не роняют сессию.
